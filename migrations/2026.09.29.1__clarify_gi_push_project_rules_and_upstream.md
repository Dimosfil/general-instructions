# Clarify GI Push With Project Rules And Missing Upstream

Migration ID: `2026.09.29.1__clarify_gi_push_project_rules_and_upstream`

## Purpose

Prevent a project default that users normally commit from being mistaken for
an unconditional ban on the explicit `gi пуш` commit-and-push command. Handle
branches without an upstream before creating a partial Git finish.

## Accepted Guidance

- `gi пуш` / `ги пуш` explicitly authorizes one scoped commit and a push;
  `gi только пуш` pushes existing commits without making a commit.
- A project-local default that the user normally commits allows these explicit
  commands. Preserve a project-local unconditional ban when it is intentional;
  report the conflict rather than silently overriding it or reinterpreting
  `gi пуш` as push-only.
- Do not advise a manual commit followed by `gi пуш`: without scoped changes to
  commit, that command does not fall back to a push.
- Check the branch upstream before staging for a push. If it is absent, obtain
  the intended remote branch and set tracking on the first push. Do not infer
  the destination from another remote branch containing the current HEAD.
