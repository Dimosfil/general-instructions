# Authoritative Configurable Behavior

Version: `2026.11.20.1`

## Accepted Contract

Store changeable entity-specific limits, defaults, supported combinations,
field mappings and compatibility selections in the authoritative project
contract/configuration. Keep reusable algorithms in code with explicit contract
inputs. Review identifier-selected branches at the owner of the policy.

Unavailable target storage requires a versioned declarative change package
for the existing migration/import mechanism. Preserve runtime ownership and
failure behavior, verify feasible offline scenarios and report application
and live verification as pending. Document necessary executable exceptions
with their constraint, owner, scope, verification and removal condition.

- Verify all three installed files carry the contract and their links resolve.
- Confirm unavailable storage leaves application/live verification explicitly
  pending and cannot silently select another runtime source.
- During authorized product changes, inspect policy ownership and verify the
  normal entry point consumes changed contract data. Use the project's existing
  checks where sufficient and document any necessary executable exception.
- For source maintenance, run whitespace, release-order, routing,
  task-verification and bootstrap checks against the fixed prior release ref.
- Record installation and version after file-delivery checks pass. Keep host
  activation and product runtime verification separate from installation.
