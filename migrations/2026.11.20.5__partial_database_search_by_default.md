# Partial Database Search By Default

Version: `2026.11.20.5`

## Accepted Contract

For read-only database searches, including raw output, treat textual names and
identifiers as partial-match terms by default. Use exact equality when the user
explicitly requests it (for example `ТОЧНО!`) or provides an explicit SQL
predicate. Raw output controls value preservation and presentation, not a
mandatory equality operator.

## Apply

1. Merge the read-only matching rule from
   `patterns/AGENTS_RUNTIME/07-scope-and-evidence.md` before its raw table rule.
   Respect project search contracts; otherwise use case-insensitive literal
   substring matching against relevant name/identifier fields, with parameters
   and escaped LIKE wildcards unless the user requested a pattern.
2. Do not infer exact intent from quotes or identifier-like input. Preserve
   explicit SQL, other requested filters and all matching variants/providers
   within disclosed limits. Show the actual query/filter; an empty equality
   lookup does not prove absence for a partial search.
3. Preserve raw table orientation and the explicit JSON override. Do not extend
   the discovery default to updates, deletes, permission changes or other
   mutations.
4. Advance fresh-bootstrap template version/checkpoint to this release while
   preserving unrelated project instructions and settings.

## Verify And Record

- Review a short term matching a longer stored identifier, explicit exact
  matching, quoted input, literal wildcard input and multiple matches against
  the installed rule. Confirm raw formatting and mutation scope remain intact.
- For source maintenance run whitespace, fixed-baseline release-order,
  routing/context-budget and bootstrap checks.
- Record installation after file verification. No live database access or data
  writes are needed for this instruction-only update.
