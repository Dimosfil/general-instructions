# Isolate Optional Configuration Failures

Migration ID: `2026.09.28.1__isolate_optional_config_failures`

## Purpose

Keep an invalid optional integration setting from taking down a service while
detecting invalid settings required by the core during development.

## Accepted Guidance

- Classify external settings by the capability that needs them. Document safe
  defaults for optional settings, including a disabled state for absent
  credentials. Validate all external overrides before use.
- For invalid optional settings or provider-rejected optional credentials, keep
  the core healthy, disable the dependent backend action and UI control, show a
  sanitized reason, and log a sanitized diagnostic. Never treat placeholder
  secrets as working credentials.
- Document startup-critical settings in the project run contract. Fail clearly
  when they are invalid and cover missing and malformed cases in local startup
  and relevant tests or preflight checks.
