# Define Standalone Git Finish Scope

Migration ID: `2026.10.01.1__define_standalone_git_finish_scope`

## Purpose

Let standalone commit commands work in a new chat without repeatedly asking
the user to supply task history or choose all current changes.

## Accepted Guidance

- Resolve commit scope from explicit user-selected changes, then the active
  conversation task, otherwise the standalone command's repository scope.
- Without selection or an active task, `gi commit`, `gi push`, and
  `gi commit push`, including Russian aliases, select current eligible tracked
  and untracked changes in the verified repository, including pre-existing
  user changes. Do not ask solely because history is absent or many files differ.
- Inspect changes and briefly report scope and exclusions before staging.
  Exclude secrets, prohibited payloads, generated noise, and separately reserved
  work. Preserve active-task boundaries; ask only about concrete conflicting
  scope instructions or inseparable excluded changes.
- Preserve commit/push authorization, upstream checks, Git-only finalization,
  and `gi only push` behavior. Do not add implementation or repair work.
