# Verify Contracts Before Git Finish

Migration ID: `2026.09.27.1__verify_contracts_before_git_finish`

## Purpose

Prevent meaningful feature or architecture changes from being committed while
their portable behavior contracts are incomplete or stale.

## Accepted Guidance

- Before completing meaningful implementation work, compare the scoped diff
  with current source, tests, focused project-memory specs, and affected
  user-facing documentation. Cover changed workflows, states, failure paths,
  invariants, data semantics, and architecture decisions.
- Before staging a scoped implementation change for commit or push, complete
  the same check. Correct an omission within the original task scope first;
  otherwise stop Git finish and report the exact gap.
- Keep project memory as concise, current contracts and evidence links. Store
  code, tests, human documentation, logs, and generated artifacts in their own
  project locations. Revise stale specs instead of appending task transcripts.
- A passing test suite, handoff summary, or clean Git diff does not replace the
  contract check. Keep the check proportional to the changed scope.
