# Enforce Evidence-Based Automatic Updates

Version: `2026.10.23.1`

## Purpose

Prevent an availability-only startup helper from being mistaken for a user
opt-out. Complete accepted updates automatically when policy permits them.

## Apply

1. Merge the update evidence and agent-execution clauses from the source
   `AGENTS.md` / `templates/AGENTS.template.md` into the project entrypoint.
   Merge the corresponding rules in `patterns/AGENTS_RUNTIME/07-startup.md`
   and `patterns/INSTRUCTION_KIT_MIGRATIONS.md`; update the command contract
   if `patterns/GI_COMMAND_CONTRACTS.md` is installed.
2. Refresh `tools/check-instruction-kit-updates.ps1` from
   `templates/check-instruction-kit-updates.template.ps1`. Merge the update
   checker delegation in `tools/get-gi-context.ps1`. If a legacy
   `tools/agent-start.ps1` only prints availability, replace its shared startup
   flow from `templates/agent-start.template.ps1`, preserving local selectors
   and project-specific startup hooks. Deliver missing context-builder/router
   files through the accepted earlier routing migrations when necessary.
3. Preserve project metadata and opt-outs. Missing `enabled` and
   `auto_apply_pending_migrations` default to true. Reject non-boolean values;
   do not overwrite them. Only current JSON false with path/key/value evidence
   permits a disabled report. Helper limitations are not policy evidence.
4. When enabled and pending, the agent reads and applies accepted migrations
   immediately without another command or confirmation. Verify actual file
   changes before `-RecordApplied`; then recheck version and pending count.
   Report actual access, conflict, or scope blockers without inventing opt-outs.

## Verify And Record

Check missing/true/false/invalid settings, legacy notices, and the real
checker-to-context-builder handoff. Confirm checks do not advance metadata,
disabled reports include exact evidence, and unavailable sources have unknown
pending count. Run scoped routing and bootstrap checks and `git diff --check`.
Only after verified application, record this migration and version. On conflict,
preserve unrelated changes and leave the unapplied migration pending.
