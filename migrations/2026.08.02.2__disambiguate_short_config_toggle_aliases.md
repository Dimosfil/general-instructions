# Disambiguate Short Config Toggle Aliases

Migration ID: `2026.08.02.2__disambiguate_short_config_toggle_aliases`

## Purpose

Ensure natural Russian `он/офф` aliases control project-wide config-service
integration and cannot be confused with the separate app self-registration
toggle.

## Accepted Guidance

- Accept `gi config on/off`, `gi конфиг вкл/выкл`, `gi конфиг он/офф`,
  `ги конфиг вкл/выкл`, and `ги конфиг он/офф` as project-integration toggles.
- Interpret any short `gi config <toggle>` / `ги конфиг <тумблер>` form without
  `service`/`сервис` as the whole-project integration toggle.
- Require the explicit `gi config service <toggle>` /
  `ги конфиг сервис <тумблер>` form for app self-registration.
- Map `on`, `вкл`, and `он` to `true`; map `off`, `выкл`, and `офф` to `false`.
- After disabling integration, ordinary local startup must use documented
  project-local runtime config and must not require config-service availability.

## Conflict Handling

If a project already defines these aliases differently, preserve its current
saved state but replace the ambiguous routing with the accepted distinction:
short form for project integration, explicit `сервис` form for app
self-registration.
