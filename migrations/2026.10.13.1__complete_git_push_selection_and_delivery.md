# Complete Git Push Selection And Delivery

Migration ID: `2026.10.13.1__complete_git_push_selection_and_delivery`

## Purpose

Make explicit all-changes requests override task defaults, keep modifiers visible
in context, and complete push delivery even when no new commit is needed.

## Accepted Guidance

- `gi push all`, `ги пуш всё`, `ги пуш все`, and equivalent commit/commit-push
  forms explicitly select all eligible current repository changes, including
  staged, unstaged, untracked, deleted, and pre-existing work. Preserve safety
  exclusions and concrete separate-work reservations. Do not extend to ignored
  files, other repositories, worktrees, branches, or force-push.
- Ordinary standalone push in a new chat already uses repository scope. Old
  summaries alone do not establish an active task or silently narrow selection.
- Preserve full requested command text in the resolver's context packet.
- Reconcile the staged diff against every selected eligible change. Inspect
  existing staged content and never commit exclusions or silently reset the index.
- If no new commit is needed, push existing outgoing commits after compact Git
  safety checks. Remove the old no-changes prohibition on push-only fallback;
  never skip selected changes, create an empty commit, or demand a second command.
- After finish, report each remaining changed path with its reason or blocker.
  Eligible selected residue means incomplete work even when upstream matches.
