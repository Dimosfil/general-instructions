# Sync Upstream Before Push

Version: `2026.10.25.6`

## Accepted Contract

A push request authorizes fetching and integrating upstream changes before a
normal push. Fast-forward when possible; otherwise use a normal merge preserving
both histories. GI does not require a pull request for this synchronization.
Preserve explicit project-local PR requirements. Never force-push, discard
either history or rebase published commits. Stop on conflicts or obstructing
local changes rather than overwriting them.

## Apply

1. Merge the revised push synchronization rule from
   `patterns/AGENTS_RUNTIME/16-git-policy.md` and the
   `Preserve Published Main-Branch History` section of `patterns/GIT_WORKFLOW.md`.
   Replace the previous blanket stop on divergent committed histories with safe
   pull/merge integration; keep the stop on conflicts, failed fetch and uncertain
   destination. Require fetched-tip ancestry before a normal push.
2. Merge the corresponding Git rule from
   `templates/AGENT_WORKING_AGREEMENTS.template.md` into installed agreements
   when present. Preserve unrelated customizations and stricter project rules.
   Update the focused Git-finish memory contract without replacing product specs.
3. Preserve the ban on forced retries and API/ref bypasses. After a rejected
   push, inspect fresh remote state and integrate safely only when incoming
   commits caused the rejection. Never auto-stash unrelated work or choose one
   side wholesale to suppress conflicts. Server settings remain a separate task.
   Use explicit no-rebase pull or fetch/merge. Preserve push-only's ban on new
   commits: fast-forward integration is allowed, a required merge commit blocks it.

- Source maintenance runs routing, bootstrap and release-order checks against

  divergent committed histories and conflicts without losing either side.
- Record the migration/version only after delivery checks pass; recheck pending
