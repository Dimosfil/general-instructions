# Add Modular Service Agent Guidance

Migration ID: `2026.09.28.2__add_modular_service_agent_guidance`

## Purpose

Give agents a repeatable way to design, implement, integrate, and evolve a
large system made of modules without assuming that each module is a separate
deployable service.

## Source Files And Project Targets

- Copy `patterns/MODULAR_SERVICE_ENGINEERING.md` from the accepted source into
  the consuming project's `patterns/` folder if missing. Refresh an existing
  shared copy while preserving project-owned adaptations.
- Refresh the modular-system guidance in
  `patterns/AGENTS_RUNTIME/04-content-and-authoring.md` from the accepted
  source. Add the compact rule and pattern link to project `AGENTS.md` only if
  the project has no equivalent local routing; preserve its project-specific
  instructions.
- Copy `templates/SYSTEM_MAP.template.md`,
  `templates/MODULE_PASSPORT.template.md`, and
  `templates/MODULE_CONTRACT.template.md` into the project's `templates/`
  folder if missing. Refresh existing shared copies without replacing
  project-specific versions.
- Where `GENERAL_DEVELOPMENT_PLAYBOOK.md` is installed, add its modular-system
  guidance without rewriting unrelated sections. Do not create project-specific
  maps or passports until a concrete modular system needs them.
- Add the new pattern and templates to `copied_files` in
  `tools/project-memory/instruction-kit.json`, then advance the installed
  version and migration checkpoint after the file changes are verified.

## Verify

- Check that the runtime rule resolves to the copied pattern and that all
  three template paths exist.
- Check that local `AGENTS.md` points to the pattern or provides an equivalent
  project-local route.
- Check that copied guidance preserves the distinction between logical modules
  and deployable services, and that the system, module, and contract templates
  name data ownership and assembled-workflow verification.
- Run `git diff --check` where Git is available and inspect the changed-file
  list for unrelated edits.

## Conflict And Rollback

If project-owned guidance or templates conflict, preserve them and report the
specific conflict before recording this migration as applied. Roll back the
copied guidance, templates, version, and metadata checkpoint together.
