# Generalize Project Tester Information And Start

Migration ID: `2026.10.03.2__generalize_project_tester_info_and_start`

## Purpose

Make the shared tester reusable across projects. Keep concrete scenarios,
modes, settings, links, runtime commands, inputs, and artifacts project-local.

## Accepted Guidance

- `gi test` / `ги тест` now explains tester information and local scenarios
  without execution or runtime mutation. This supersedes its former meaning
  as an immediate full-system test.
- `gi test start` / `ги тест старт` runs the selected local scenario with
  authorization, checkpoints, current evidence, and verified restoration.
- Preserve explicit `gi full test`, `gi release test`, and `gi system test`
  full-system behavior in a dedicated module. Apply that flow to test-start
  only when its selected scenario explicitly requires full-system verification.
- Each project defines its own canonical testing entrypoint and contracts.
  Do not copy one project's URLs, modes, providers, fixtures, or result codes
  into shared defaults. The optional scaffold is not an installed runner.

## Source Files And Project Targets

- Copy `patterns/AGENTS_RUNTIME/09-testing.md` and create/copy
  `patterns/AGENTS_RUNTIME/09-full-testing.md` at corresponding project paths.
  Merge any project-owned scenario rules into their existing local contracts.
- Merge the `test`, `test-start`, `test-task`, and `test-full` route records from
  `config/gi-command-routes.json`; replace the old generic execution route,
  preserve unrelated/local routes, and resolve overlapping test aliases to the
  accepted information/start meanings without dropping local scenario content.
- Merge command meanings into local `COMMANDS.md` and, where used,
  `patterns/GI_COMMAND_CONTRACTS.md`. Update the testing pointers in local
  `AGENTS.md` using `templates/AGENTS.template.md`.
- Merge the tester bullets from `templates/AGENT_WORKING_AGREEMENTS.template.md`
  into local working agreements. Replace old instructions that treat bare
  `gi test` as execution; preserve stricter local safety and verification gates.
- Copy `templates/PROJECT_TESTING.template.md` as an optional scaffold. Merge
  the testing entrypoint guidance from `templates/AGENT_RUNBOOK.template.md`
  only where missing; retain actual commands and canonical scenario links.
- Merge the tester/full-system pointers in the compatibility index
  `patterns/AGENTS_RUNTIME/09-project-operation-commands.md` when present.
- Add new copied rule/scaffold paths to local instruction-kit metadata.
  Record the version/checkpoint only after changes and verification succeed.

## Merge Boundaries And Verification

- Preserve product-specific test prompts, settings, links, data connections,
  roles, inputs, output locations, historical results, and private backups.
- Applying this migration does not authorize a product test run, installation
  of a harness, state reset, product fixes, or edits in other projects.
- Verify information, start with trailing task text, task/plan, and full-system
  aliases through the local resolver. Ordinary start must not load the reset
  module; full-system routing must include its dedicated module.
- Check linked files, local-rule consistency, metadata, and `git diff --check`.
  Run routing/bootstrap regressions in the shared library when available.

## Rollback

Restore prior instruction text, routing, and metadata together. Preserve local
product scenarios, runtime state, test evidence, and backups.
