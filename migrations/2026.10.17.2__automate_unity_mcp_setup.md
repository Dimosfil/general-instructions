# Automatic Unity MCP setup

## Contract

Provision Unity MCP during GI initialization, after accepted updates (including
zero pending migrations on a new host), and once on the first Unity task of a
session. Ordinary projects do not read host config, install Unity dependencies,
or start the backend. The host router returns an empty catalog outside Unity.

## Apply

1. Copy these missing project-owned artifacts from the accepted source:
   - `config/unity-mcp.json`
   - `docs/unity-mcp-router.md`
   - `tools/ensure-unity-mcp.ps1`
   - `tools/unity-mcp-router.mjs`
   - `tools/verify-unity-mcp.mjs`
   Merge existing project-owned versions deliberately, preserving opt-outs and
   local configuration; do not require a runtime path to the shared source.
2. Merge the source's automatic setup contract from
   `patterns/AGENTS_RUNTIME/20-unity-projects.md`, the startup rule in
   `07-startup.md`, and the narrow authorization exception in
   `10-private-scope-and-missing-context.md`. Keep the existing live project,
   scene, current-chat verification, and Editor-state safeguards.
3. Merge `tools/get-gi-context.ps1`'s Unity-only setup section for `start` and
   `update`. Preserve unrelated local context-builder behavior. Keep setup
   outside the migration check's zero-pending fast path, not inside the
   checker. If bootstrap contracts are copied locally, merge their setup step
   from `BOOTSTRAP.md` and `patterns/SHARED_INSTRUCTIONS_BOOTSTRAP.md`.
4. Keep a discoverable Unity/automatic-setup pointer in the local `AGENTS.md`
   without replacing project-specific instructions. Add the five delivered
   artifacts to `copied_files`. Default absent `unity_mcp.enabled` to true;
   add `{ "unity_mcp": { "enabled": true } }` only when that policy is absent.
   Preserve explicit false, custom server configurations, and project opt-outs.
5. For a Unity root, run the installed
   `tools/ensure-unity-mcp.ps1 -ProjectPath <active-project-root>` using the
   bounded authorization in module 20. Reuse an already returned setup result.
   Let it discover current host paths; never copy the source machine's paths.
   Non-Unity targets return without touching the host.

## Verify and record

- Verify all delivered artifact paths and the entrypoint/runtime references.
- Confirm setup is called for Unity initialization/start/update and skipped for
  ordinary projects. A transferred project must also provision a fresh host
  when the instruction versions match.
- Run setup/check in the active project and report configuration, package,
  protocol discovery, live Editor state, and tools in this chat separately.
  Use discovered read-only Editor tools to establish project/scene identity
  when an Editor is available; the standalone probe cannot establish chat
  availability. Never open an Editor or launch interactive login to pass a check.
- Treat missing login, failed downloads, unsupported tools/versions, custom
  server conflicts, filesystem errors, and unavailable Editor as specific
  host/live blockers. Preserve completed independent work and allow subsequent
  sessions to retry. Do not record a successful host connection for these cases.
- Run `git diff --check` for the delivered files. Record this migration only
  after its project-owned instruction/tool delivery is complete and verified.
  An independently reported host/live blocker is separate from instruction
  delivery and must remain visible in the result, not hidden by the checkpoint.
