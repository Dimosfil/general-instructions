# Preserve Published Main-Branch History

Version: `2026.10.25.5`

## Accepted Contract

Preserve published history on `master`, `main` and the repository's default
branch. Never force-push, delete/recreate or replace that history through
Git, an API or a host UI. A force-with-lease is still a history rewrite.
Ordinary push, sync, repair and all-changes requests grant no exception.

## Apply

1. Merge the published-history rules from
   `patterns/AGENTS_RUNTIME/16-git-policy.md` and the
   `Preserve Published Main-Branch History` section of `patterns/GIT_WORKFLOW.md`
   into installed instructions. Preserve stricter project rules and unrelated
   customizations. Require a fetch of the intended destination and fast-forward
   ancestry before a normal push. Stop on divergence, failed fetch, uncertain
   destination or rejected push; use new corrective commits/reverts for repairs.
2. Merge the matching Git rule from
   `templates/AGENT_WORKING_AGREEMENTS.template.md` into the project's installed
   working agreements, if present. Keep detailed contracts in project memory
   aligned without replacing product specifications.
3. Keep server enforcement separate: inspect effective settings before claiming
   protection. Recommend blocking force pushes, deletion and administrator
   bypass; do not change remote settings without an explicit protection request.

## Verify And Record

- Inspect Git-finish context for the main-branch prohibition, force-with-lease
  coverage, ancestry requirement, rejection handling and enforcement distinction.
- In source maintenance run routing, bootstrap and release-order checks with an
  explicit previous published ref. Do not copy development tests to consumers
  or run destructive trial pushes against a real main branch.
- After file delivery checks pass, record this migration/version in kit metadata
  and recheck pending count. Report host settings independently; installed
  instructions do not prove that the host will reject a force push.
