# Keep Git Finish Within Established Scope

Migration ID: `2026.09.22.6__keep_git_finish_within_established_scope`

## Purpose

Prevent commit/push commands from expanding an ambiguous dirty worktree into a
new implementation, repair, runtime-cleanup, or release task.

## Accepted Guidance

- Resolve Git-finish scope only from the active task in the current conversation
  or an explicit user-selected path/change set.
- Never infer that all dirty files form one task from apparent similarity,
  recency, or the possibility of making them pass together.
- When scope is ambiguous, stop before staging or filesystem writes and ask the
  user what to include.
- Treat finish-time verification as evidence, not new implementation authority.
  Correct a failure only when scoped work caused it and the original task already
  authorizes the correction; otherwise report the blocker.
- Do not rewrite unrelated tests, delete runtime state, change dependencies,
  restart/rebuild services, or perform broad cleanup solely because a Git-finish
  command was requested.
- Add an ignore rule during finish only for active-task output or when that
  ignore change was already authorized. Leave unrelated prohibited content
  unstaged and report it.
